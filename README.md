# Эмулятор UNIX-оболочки — вариант 18

Практическая работа № 1 по дисциплине «Конфигурационное управление»,
ИКБО-42-25. Реализация на Python 3.9+ без внешних зависимостей.

## Этап 1. REPL

Консольный диалог, приглашение с именем VFS, раскрытие переменных
окружения реальной ОС, команды-заглушки `ls`, `cd` и команда `exit`.

```bash
python3 src/main.py
```

Примеры: `ls $HOME`, `cd /tmp`, `unknown`, `exit`.

## Этап 2. Конфигурация

`--vfs DIR` задает физический каталог для загрузки VFS, `--script FILE`
указывает стартовый скрипт, `--no-interactive` завершает программу после
выполнения скрипта. В начале запуска выводятся параметры конфигурации.
Строки скрипта, начинающиеся с `#`, являются комментариями. Ошибка
отображается с номером строки, а выполнение продолжается.

```bash
sh tests/scripts/config_default.sh
sh tests/scripts/config_custom.sh
```

## Этап 3. Виртуальная файловая система

Источник VFS — каталог реальной ОС, который рекурсивно читается в память.
Символические ссылки запрещены. Если файл `motd` есть в корне VFS, его
содержимое отображается при запуске. В отсутствие `--vfs` создается VFS
по умолчанию. `vfs-init` сбрасывает память к состоянию по умолчанию;
**при использовании `--vfs` команда удаляет все содержимое физического
каталога VFS**, как прямо требует вариант 18. Используйте только специально
созданный тестовый каталог — не указывайте свои рабочие директории.

```bash
sh tests/scripts/vfs_minimal.sh
sh tests/scripts/vfs_simple.sh
sh tests/scripts/vfs_deep.sh
```

## Этап 4. Основные команды

- `ls [PATH]` — вывести содержимое каталога или имя файла.
- `cd [PATH]` — перейти в каталог; без аргументов перейти в `/`.
- `cat FILE [FILE...]` — вывести содержимое одного или нескольких файлов.
- `who` — вывести имя пользователя реальной ОС и тип консоли.
- `uniq FILE` — вывести файл без соседних повторяющихся строк.

Относительные пути вычисляются из текущей виртуальной директории,
поддерживаются `/`, `.`, `..`. Вариант `uniq` без аргументов не
реализован, так как эмулятор не имитирует перенаправление стандартного ввода.

```bash
python3 src/main.py --vfs tests/vfs/deep \
  --script tests/startup/stage4.emu --no-interactive
```

## Этап 5. Дополнительные команды

- `mkdir DIR [DIR...]` — создать новые каталоги только в памяти VFS.
- `rm FILE [FILE...]` — удалить файлы только в памяти VFS; для
  безопасности каталоги не удаляются (рекурсивный режим отсутствует).
- `vfs-init` — особая служебная команда, которая **в отличие от `rm`**
  очищает и физическое представление загруженной VFS.
- `exit` — завершить работу эмулятора.

```bash
python3 src/main.py --vfs tests/vfs/deep \
  --script tests/startup/stage5.emu --no-interactive
sh tests/scripts/test_reset.sh
```

## Структура проекта

```text
src/              исходники парсера, VFS и команд
 tests/           модульные тесты и примеры запуска
 tests/startup/   сценарии команд эмулятора
 tests/scripts/   сценарии реальной оболочки ОС
 tests/vfs/       минимальная, простая и вложенная VFS
 run.sh          запуск в Linux/macOS
 run.bat         запуск в Windows
 Makefile        запуск, тесты и демонстрация
```

## Запуск и тестирование

Необходим Python версии 3.9 или новее. Дополнительные пакеты не нужны.
На Windows можно использовать `run.bat` вместо `run.sh`.

```bash
./run.sh --vfs tests/vfs/deep
./run.sh --script tests/startup/stage4.emu --no-interactive
make test
# или универсальный способ:
python3 -m unittest discover -s tests -v
```

Синтаксис переменных окружения: `ls $HOME` на UNIX-подобных ОС. На Windows
для раскрытия переменных с помощью `os.path.expandvars` можно использовать
`%USERPROFILE%`. Кавычки для группировки аргументов поддерживаются.

Сценарии `stage2.emu`–`stage5.emu` включают ошибочные команды, чтобы
проверить сообщение об ошибке и продолжение выполнения скрипта.
Скрипт `test_reset.sh` создает временную директорию и проверяет физическое
удаление только в ней, не затрагивая тестовые исходные данные.
